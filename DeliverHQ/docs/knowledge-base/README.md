# 知识库（Knowledge Base）

> 来源：企业微信团队"AI 代码生成率 94%"经验总结。
> 核心原则：**AI 提效的天花板，既在模型，也在工程。references/ 比 tools/ 体量更大。**

## 三级金字塔结构

```
L1-项目总览/     ← AI 入场的"大堂导览"（< 5KB）
L2-模块级/       ← 文件粒度的"街道地图"
L3-语义桥/       ← 抹平"设计/协议"和"代码"的鸿沟
```

## L1：项目总览

告诉 AI 项目有哪些模块、各自负责什么。

- **文件**：`L1-项目总览/overview.md`
- **大小**：< 5KB
- **用途**：五步定位法第 1 步，1 秒选出模块

## L2：模块级

每个模块的文件登记表（Controller/Service/Model/Helper 分组）。

- **文件**：`L2-模块级/<module>.md`
- **元数据**：module_id / root_dirs / desc / sha_baseline
- **用途**：五步定位法第 2 步，5 秒锁定文件（不用读源码）

## L3：语义桥

产品语言 → 代码指令的翻译层。

| 文件 | 用途 |
|------|------|
| `glossary.md` | 业务术语 → 代码命名的映射表 |
| `naming-conventions.md` | 设计 token → 代码实现的规范 |
| `search-matrix.md` | 5维搜索矩阵（定位用） |

## 核心效果

> **总 token 消耗：从"全项目灌入"的 ~10M+ 降到 ~30K — 300× 的压缩比。**

## 自维护机制

### check_project_wiki_stale.py

- **SHA 基线缓存**：文件变化时自动 flag "待复核"
- **三色分诊清单**：新增 / 删除 / 大改三类信号分开列
- **pre-commit hook 阻断**：有 stale 信号 → 阻止提交

### 知识库 + 定位法：1 + 1 > 2

1. 从 L1 总览里 1 秒选出模块（不用 grep）
2. 从 L2 模块 wiki 里 5 秒锁定文件（不用读源码）
3. 进入文件后 rg 精准搜索
4. 只读相关片段（~10K token）
5. 写代码前先查 L3 映射表
