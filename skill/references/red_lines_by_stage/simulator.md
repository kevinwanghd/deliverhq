# 模拟器验证阶段红线（simulator）

> 加载时机：进入「模拟器验证」阶段时
> 违反后果：无限重试，效率低下

---

## RL-S07：阶段内重试不超过 2 轮

### 规则

> 模拟器验证阶段内重试不超过 2 轮

### 原因

避免陷入无限重试循环：
- 如果同一问题重试超过 2 次仍然失败
- 说明问题不是脚本/时序问题
- 可能是验证设计错误或代码 bug

### 重试范围（A/B/C 分类）

| 类型 | 问题 | 是否可重试 |
|------|------|------------|
| A 真问题 | 代码 bug | ❌ 回「实现」阶段 |
| B 路径不通 | 验证设计错 | ❌ 修订 verify_plan |
| C 脚本/时序 | 可自修复 | ✅ ≤2 轮重试 |

### C 类可重试问题

- 元素未渲染就 tap（时序问题）
- 坐标算错（逻辑像素 vs 物理像素）
- 输入法没切到位

### 正确流程

```
第 1 次验证：FAIL（C 类：元素未渲染）
  → 等待 1 秒后重试
第 2 次验证：FAIL（仍然是 C 类）
  → 调整时序后重试
第 3 次验证：
  → 如果还是 C 类，强制停下
  → 如果变成 A/B 类，切换处理方式
```

### 禁止行为

- 同一问题重试超过 2 次
- 遇到 A/B 类问题还在重试验证脚本
- 忽略失败原因继续下一步

### 触发报告模板

```markdown
⛔ 触发红线 RL-S07：阶段内重试超过 2 轮

当前情形：
- 重试次数：{retry_count}
- 问题类型：{problem_type}
- 最后错误：{last_error}

建议处理：
1. 如果是 A 类（代码 bug）：返回「实现」阶段修复
2. 如果是 B 类（验证设计错）：修订 verify_plan 或跳过
3. 如果是 C 类（可自修复）但超过 2 轮：强制停下，报告用户
```
