# 需求拆解阶段红线（breakdown）

> 加载时机：进入「拆解」阶段时
> 违反后果：污染工程规范，漏实现或越界

---

## RL-S04：禁止遗漏设计稿

### 规则

> 每张设计稿都必须归宿明确，不允许出现"未归类"

### 三类归宿

| 类型 | 说明 | 处理 |
|------|------|------|
| 新增 | 全新页面/组件，需要开发 | 创建 subtask |
| 修改 | 现有页面的改动，需要改代码 | 创建 subtask |
| 忽略 | 与本期需求无关 | 记录忽略原因 |

### 禁止行为

- 用"参考图"当万能垃圾桶
- 只挑部分设计稿做需求点
- 不明确标注"忽略"的原因

### 正确示例

```markdown
| 设计稿 | 类型 | 理由 |
|---------|------|------|
| 153:74513 | 新增 | 新增小红条 UI |
| 153:74600 | 修改 | 角标样式调整 |
| 153:74521 | 忽略 | 通用模板，与本期无关 |
```

## RL-S06：禁止 LLM 手工分桶

### 规则

> Figma 设计稿筛选必须用脚本直方图，禁止 LLM 凭手感分桶

### 正确流程

1. 运行 `scan_figma_frames.py` 出直方图
2. LLM 在已分桶基础上**补判** `UNCERTAIN` 项
3. 每项必须有明确的 `nodeId` 引用

### 禁止行为

- LLM 凭印象决定某张设计稿是否需要开发
- 不运行脚本，直接给出分桶结果
- 用"看起来相关"作为判断依据

### 正确示例

```bash
# 1. 先运行脚本
$ python scan_figma_frames.py --figma-link "..."

# 2. 脚本输出直方图
| 设备 | 候选稿数 | 说明 |
|------|----------|------|
| iPhone 15 Pro | 3 | 待人工确认 |
| iPhone SE | 1 | 确认新增 |

# 3. LLM 只补判 UNCERTIAN 项
UNCERTAIN: 153:74599
判断依据：[设计稿 nodeId 标注说明]
```

## RL-S08：设计稿筛选必须用脚本

### 规则

> 六类输入每类都有专用脚本通道，严禁通用 web_fetch

### 数据源与专用工具

| 数据源 | 专用工具 | 禁止使用 |
|--------|----------|----------|
| 企微文档 | `wecom-cli` | `web_fetch` |
| TAPD 需求 | `tapd_mcp_http` MCP | `web_fetch` |
| Figma 设计稿 | `fetch_figma_mcp.py` | `web_fetch` |
| 代码搜索 | `rg` / `grep` | LLM 猜测 |
| 项目知识库 | `knowledge-base/` 目录 | 无参照发明 |

### 禁止行为

- 用 `web_fetch` 获取企微文档（只拿到 HTML 外壳）
- 用 `web_fetch` 获取 TAPD 描述（拿不到 markdown）
- 直接 grep 全项目而不先查知识库
