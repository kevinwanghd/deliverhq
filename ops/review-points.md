# DeliverHQ 审查要求

## 审查要点

只报会导致错误、回归、数据/密钥泄露或契约破坏的问题，不报风格。

- 安全：不把密钥、token、账号写入代码、示例配置、日志或测试夹具；新增外部请求默认 HTTPS。
- 错误处理：不得静默吞异常；报错要带足够上下文。
- 测试：行为变化要有对应测试；删除测试或标记 skip 必须说明理由。
- 契约：CLI 参数、发布脚本、配置键变化必须同步 docs 与 CHANGELOG。
- 范围卫生：无关文件、生成物、大二进制不混入；lockfile 只在依赖真实变化时更新。
- 跨平台：脚本与路径要兼容 Windows 与 Linux（发布流程两处都会跑到）。
